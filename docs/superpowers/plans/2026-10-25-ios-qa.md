# iOS 10월 20일 QA Implementation Plan

**Goal:** 노션 iOS QA 8건의 원인을 수정하고 컴포넌트·런타임 검증 결과를 남긴다.
**Architecture:** 기존 TCA state/action/reducer와 domain/data 경계를 유지한다. 표시 데이터는 선택 레코드에서 전달하며 중복 상태를 만들지 않는다.
**Tech Stack:** SwiftUI, TCA, Swift Package Manager, XCTest/Swift Testing.
**Spec:** `docs/screens/1_login.md`, `0_onboarding_guide.md`, `2_home.md`, `2_home_dark.md`, `3_calendar.md`, 각 노션 티켓의 2026-10-25 원인 분석.

## 구현 순서

- [ ] Home/Calendar: 이미지 상태를 버튼에 전달하고 등록/보기 표현 전환. Calendar 좋아요 선택 상태 전달. 기존 레코드 ID 및 날짜 전환 계약 유지.
- [ ] Home/Calendar: Figma 복사 토스트 재사용, 캘린더 복사 완료·해제 액션 연결. 반복 복사/이탈 시 타이머 취소 검증.
- [ ] Home 달력 연도: 지역화 정수 보간 대신 문자열로 표시. 메뉴를 열어 쉼표 없는 연도와 선택 동작 확인.
- [ ] Typing: Figma 캐릭터·안내문구 자산/배치 적용. 키보드·한글 조합 및 저장 버튼 가림 회귀 확인.
- [ ] Login: 원본 로고·Apple/Kakao/Google 구성, 정확한 약관 링크 영역. Google SDK 인증과 기존 서버 로그인 연결, URL scheme 및 설정 검증.
- [ ] Onboarding: 확정된 노출 정책에 따라 로그인 이후 기존 가이드 경로 재사용. 완료/건너뛰기/재로그인/미로그인 차단 검증.
- [ ] Typing 저장: 완료/연속 완료/미완료 상태와 Figma 팝업 연결. 실패 시 입력 보존, 중복 저장·재시도·과거 날짜 검증.
- [ ] 관련 단위/UI 테스트, Figma 컴포넌트·전체 캡처 대조. 노션에 실제 결과와 남은 제약 기록.

## 실행 결과 · 2026-10-25

8건의 구현을 반영했고 전체 단위·팝업 UI 142건이 통과했다. 위 체크 항목에는 실서버·작은 화면 등 미검증 범위가 포함되어 있어 전체 완료 체크로 바꾸지 않는다. 기능 결과와 시각 차이는 [QA 기록](../../design-qa/2026-10-25-ios-qa.md), 원문 포함 보고서는 [HTML](../../design-qa/2026-10-25-ios-qa-report.html)에 정리한다. Notion 상태는 In progress. 최종 Figma 수용은 프레임·폰트·기존 배경 차이로 Blocked.

## Review Focus

### 저장 팝업 확정 후 실행

1. 중복 저장 회귀 테스트 RED 확인.
2. POST v2 응답 계약, 기존 월별 완료 조회·오늘 완료 조회 재사용. 저장/뒤로가기 분리, 실패 시 입력 보존.
3. 리뉴얼 팝업 4개 상태(일반 완료는 승인된 제목 치환), 입력 포커스·배경 터치 차단 연결.
4. 현재 완료·재저장·미완료·실패·버튼 이동 reducer 테스트 및 Light/Dark 런타임 캡처.
5. 실제 결과와 시각 검증 제한을 QA·Notion에 기록.

1. 늦게 도착한 다른 날짜의 이미지/좋아요 응답이 현재 화면을 바꾸지 않는다.
2. 인증 취소·서버 실패가 세션 생성이나 Home 진입으로 이어지지 않는다.
3. 저장 실패·취소가 입력 유실이나 완료 팝업으로 이어지지 않는다.
4. 키보드/큰 글씨/Light·Dark에서 수정한 안내·버튼이 가려지지 않는다.
5. 이전 비회원 진입 경로를 되살리지 않는다.
