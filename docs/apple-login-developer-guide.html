2. Xcode에 계정과 Team 연결하기

  1. Xcode → Settings… → Accounts로 이동합니다.Android Studio의 SDK/계정 설정 화면과 비슷한 전역 설정입니다.
  2. 왼쪽 아래 + → Apple Account를 선택하고 로그인합니다.팀 목록에 방금 가입한 팀이 보여야 합니다.
  3. Fiilsa 프로젝트 → TARGETS의 Fiilsa → Signing & Capabilities를 엽니다.Automatically manage signing을 켜고 Team으로 실제 Developer Team을 선택합니다.
  4. Bundle Identifier를 확인합니다.반드시 kbhdev.Fiilsa여야 합니다. 대소문자와 점 하나까지 동일해야 합니다.
Android로 비교하면Bundle ID는 applicationId, Signing Team/Provisioning Profile은 keystore와 Play Console 앱 등록을 합친 것에 가깝습니다. 단, Xcode의 자동 서명은 인증서와 프로파일까지 함께 관리합니다.

3. App ID 등록 또는 기존 항목 확인

Developer Portal에서 Certificates, Identifiers & Profiles → Identifiers로 이동합니다.

  1. 검색창에 kbhdev.Fiilsa를 입력합니다.결과가 있으면 그 항목을 클릭하고 다음 장으로 이동합니다.
  2. 없다면 + → App IDs → App → Continue를 누릅니다.Description은 Fiilsa, Bundle ID 유형은 Explicit을 선택합니다.
  3. Bundle ID에 kbhdev.Fiilsa를 입력하고 Register합니다.Wildcard(*) App ID는 Apple 로그인용으로 사용하지 않습니다.

4. Sign in with Apple capability 켜기

  1. Identifiers에서 kbhdev.Fiilsa를 클릭합니다.Capabilities 탭 또는 capability 목록을 엽니다.
  2. Sign in with Apple을 찾아 Enable/체크합니다.오른쪽의 Configure 버튼을 누릅니다.
  3. Enable as a primary App ID를 선택합니다.Fiilsa가 처음 등록하는 독립 앱이므로 primary가 맞습니다. 이미 동일 계정 체계를 쓰는 다른 앱이 있을 때만 그룹을 선택합니다.
  4. Server-to-Server Notification Endpoint는 지금 비워 둡니다.계정 변경 알림을 받을 서버 URL이 실제로 준비된 뒤 추가합니다. 임의 URL을 넣지 않습니다.
  5. Configure 창의 Save/Done 후, App ID 화면 우측 상단 Save까지 누릅니다.경고창이 나오면 변경 내용을 확인하고 Confirm합니다.

6. 실기기에서 첫 로그인 테스트

시뮬레이터도 동작할 수 있지만, signing과 Apple Account 상태를 검증하려면 iPhone 실기기가 기준입니다.

  1. iPhone을 Mac에 연결하고 “이 컴퓨터를 신뢰”합니다.iOS 설정에서 Apple Account 로그인과 이중 인증이 켜져 있어야 합니다.
  2. Xcode 상단 실행 기기를 내 iPhone으로 바꾸고 Run(⌘R)합니다.처음이면 Developer Mode 활성화 또는 기기 등록 안내를 따릅니다.
  3. Fiilsa에서 “Apple로 시작하기”를 누릅니다.Apple 시스템 시트가 뜨고 Face ID/암호 인증이 진행되어야 합니다.
  4. 처음과 두 번째 로그인을 각각 확인합니다.이름은 최초 동의 때만 내려올 수 있으므로 두 번째에도 빈 nickname 때문에 서버가 실패하면 안 됩니다.
  • Apple 시스템 로그인 시트가 표시된다.
  • 취소하면 로그인 화면에 그대로 있고 오류 토스트가 뜨지 않는다.
  • 성공하면 Home으로 이동한다.
  • 서버 요청의 provider가 APPLE이다.
  • 앱 재실행 후 로그인 상태가 유지된다.
  • 같은 Apple Account로 다시 로그인하면 같은 회원으로 연결된다.
처음부터 다시 테스트하는 방법iPhone 설정 → Apple Account → Apple로 로그인(Sign in with Apple)에서 Fiilsa 사용을 중단한 뒤 재시도합니다. 메뉴 이름은 iOS 버전에 따라 조금 다를 수 있습니다. 실제 회원 데이터 삭제와는 별개의 동작입니다.

7. 출시 전에 서버 인증을 안전하게 완성하기

현재 앱은 Apple이 준 사용자 문자열(credential.user)을 그대로 oAuthId로 서버에 보냅니다. 클라이언트가 보낸 ID만 신뢰하면 위조 요청을 구분할 수 없으므로, “로그인창이 뜬다”와 “보안상 로그인 완성”은 다릅니다.

출시 전 필수 권장 변경앱이 identityToken과 가능하면 authorizationCode를 서버에 보내고, 서버가 Apple 공개키로 JWT 서명과 claim을 검증한 뒤 sub를 회원 ID로 사용해야 합니다.
검증 값서버가 확인할 내용
isshttps://appleid.apple.com
aud네이티브 앱 로그인에서는 kbhdev.Fiilsa
exp현재 시각보다 뒤
JWT signatureApple 공개키(JWKS)로 검증
sub검증 성공 뒤 서버 회원의 Apple 고유 ID로 저장
nonce앱에서 nonce를 사용하도록 구현하면 요청값과 일치 확인

현재 API와 권장 API의 차이

현재 UserData
{
  "oAuthProvider": "APPLE",
  "oAuthId": "credential.user",
  "nickname": "최초 로그인 이름 또는 빈 문자열",
  "profileImageUrl": ""
}

권장 확장 예시 (서버 팀과 필드명 합의 필요)
{
  "oAuthProvider": "APPLE",
  "identityToken": "eyJ...",
  "authorizationCode": "c123...",
  "nickname": "최초 로그인 이름 또는 빈 문자열"
}

이 변경은 iOS의 SocialAuthUser → LoginRequest.UserData → 백엔드 DTO/검증 로직을 함께 바꾸는 계약 변경입니다. Android로 보면 소셜 SDK에서 받은 ID token을 ViewModel에서 API DTO로 전달하고, 서버가 Firebase Admin 또는 provider 공개키로 검증하는 흐름과 같습니다.

9. 여기까지 체크되면 “1차 완료”

  • Apple Developer Program 상태가 Active다.
  • App ID kbhdev.Fiilsa가 현재 팀에 있다.
  • App ID에서 Sign in with Apple이 Primary로 활성화되어 있다.
  • Xcode Team, Bundle ID, capability, 자동 서명이 정상이다.
  • 실기기에서 최초 로그인·취소·재로그인이 통과한다.
  • 서버가 APPLE provider와 빈 이름을 처리한다.
  • 출시 전 identity token 서버 검증과 계정 탈퇴/revoke 정책을 마무리한다.
  • TestFlight에서 동일한 흐름을 다시 검증한다.
